ARCHITECTURE · ITERATION 2

A portable assurance
spine for contributions.

CVAS standardises how a project receives, verifies, reviews and retires independently produced components. It does not replace the adopting project's domain architecture.

Five cooperating surfaces

01 · Contribution surfaceForks, task briefs, templates, AI assistance, Colab and pull requests.
02 · Contract surfaceManifest, types, interfaces, preconditions, postconditions, invariants and failure semantics.
03 · Verification surfaceStructural checks, execution, reference cases, mutation, compatibility and regression.
04 · Assurance surfaceRisk classification, reviewer routing, evidence provenance and promotion status.
05 · Lifecycle surfaceSubstitution, deprecation, withdrawal, rollback and retained history.

Component contract

Every component must declare identity, version, purpose, runtime, entrypoint, tests, typed inputs and outputs, interfaces, preconditions, postconditions, invariants, state ownership, dependencies, failure behaviour, replaceability, verification obligations, risk class, licence and copyright.

Project authority remains local. The adopting project supplies canonical requirement IDs, domain schemas, interface versions, independent reference vectors, reviewer roles and release authority. CVAS must not silently invent or override these.

Composition and dependency boundaries

Consumers should depend on stable contracts rather than another component's implementation details. Dependencies and state ownership are explicit. Before withdrawal or replacement, the project computes downstream impact, validates alternatives, migrates consumers and preserves the historical evidence chain.

Intent → Component contract → Implementation
                 ↓
       Structural validation
                 ↓
  Tests + references + mutation checks
                 ↓
      Integration / impact checks
                 ↓
       Risk-based human review
                 ↓
       Project-controlled promotion

Trust boundaries

  • Fork CI is untrusted: read-only token, no secrets, no release permissions.
  • Upstream CI repeats checks against the proposed commit.
  • Protected branch rules enforce approvals and required status checks.
  • Signing, release and deployment use a separate privileged workflow.
  • Colab is a browser-accessible convenience runtime, not a hostile-code sandbox.
